# Demo Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let someone with no MENDELU account open reIS and browse all five tabs with fabricated data, so App Store Review can evaluate the app (Guideline 2.1) and Play's "App access" question can be answered.

**Architecture:** Demo is a Zustand flag plus a pre-seeded IndexedDB, with sync never started — not a fake IS transport. Entry is a React `LoginGate` screen shown when the student dismisses the native login WebView, which today strands them on a raw error string. Two network chokepoints (`fetchWithAuth`, `openExternal`) throw a typed `DemoModeError` that one handler turns into a toast.

**Tech Stack:** TypeScript, React 19, Zustand (slice pattern), IndexedDB via `IndexedDBService`, Capacitor 8, vitest + @testing-library/react, sonner for toasts, DaisyUI/Tailwind for styling.

**Spec:** `docs/superpowers/specs/2026-08-23-demo-mode-design.md`

## Global Constraints

- **Capacitor only.** `demoMode` defaults `false`; nothing in the extension or ISKAM entry points sets it. Never add a build flag for this.
- **NO `localStorage`/`sessionStorage`** — use `IndexedDBService`.
- **NO custom CSS** — DaisyUI semantic classes only (`btn-primary`, `bg-base-200`, `text-base-content/60`).
- **NO proxy/re-export files** — import directly from implementation files.
- **NO `useEffect` for data fetching.**
- **Max 200 lines per file.** Split proactively.
- **Test first.** Write the failing test, watch it fail, then implement.
- **UI strings via `useTranslation()`** reading `src/i18n/locales/{cs,en}.json`. The locale files are `cs`/`en`; the app's language code is `cz`/`en`. Do not add a `cs`→`cz` mapping.
- **Never clear the `meta` store.** Theme, language and the crash-report opt-out all live there. Demo deletes individual keys only.
- **Do not modify any parser** (`src/api/documents/parser.ts`, `src/api/cvicneTests.ts`, `src/utils/parsers/`). Nothing in this plan needs to.
- Disclaimer copy, verbatim: Czech `Neoficiální studentská aplikace. Není provozována Mendelovou univerzitou.` / English `Unofficial student app. Not operated by Mendel University.`
- Demo toast copy, verbatim: Czech `Toto je jen ukázka.` / English `This is only a demo.`

## Corrections to the spec, found while pinning interfaces

Three things the spec got wrong. Follow this plan, not those spec lines:

1. **`StudentScreen` needs no profile fixture.** It renders `pagesData` (a static IS link directory), a search box and `recentPeople` — read at `src/components/mobile/screens/StudentScreen.tsx:43-52`. It renders fine with nothing seeded. Fixture work is `studyPlan`, `studyStats` and `studyComparison` only.
2. **`studyStats` and `studyComparison` are not their own stores.** They live in `meta` under the keys `study_stats` and `study_comparison` (`src/store/slices/createStudyPlanSlice.ts:27,36`). So demo writes and deletes those two keys and must never call `IndexedDBService.clear('meta')`.
3. **`openExternal` is a second chokepoint.** `StudentScreen`'s page links go through `openExternal` (`src/mobile/openExternal.ts:89`), not `fetchWithAuth`. Guarding only `fetchWithAuth` would let a reviewer tap a page link and land on MENDELU's login in Safari.

```ts
import type { AppSlice, DemoSlice } from '../types';
import { IndexedDBService } from '../../services/storage';
import { MockManager } from '../../utils/mock/MockManager';
import { MOCK_REGISTRY } from '../../utils/mock/registry';

/** Stores the demo dataset owns outright and may safely clear. */
const SEEDED_STORES = ['exams', 'schedule', 'syllabuses', 'success_rates', 'study_plan'] as const;

/**
 * Keys inside `meta`, deleted individually.
 *
 * `meta` also holds the theme, the language and the crash-report opt-out, so
 * clearing the store to tidy up the demo would reset a student's privacy
 * choice. Delete by key or not at all.
 */
const SEEDED_META_KEYS = ['study_stats', 'study_comparison'] as const;

async function wipeSeeded(): Promise<void> {
  for (const store of SEEDED_STORES) {
    await IndexedDBService.clear(store);
  }
  for (const key of SEEDED_META_KEYS) {
    await IndexedDBService.delete('meta', key);
  }
}

export const createDemoSlice: AppSlice<DemoSlice> = (set) => ({
  demoMode: false,

  enterDemo: async () => {
    // Wiping on the way IN as well as out: a student who signs out and then
    // pokes at the demo must not see their own leftovers presented as sample
    // data, and the reverse must not happen either.
    await wipeSeeded();
    await MockManager.loadDataset(MOCK_REGISTRY.demo!);

    // Load-bearing and easy to miss. The screens gate their content on
    // handshakeDone, and demo mode never starts the sync that would set it —
    // so without this every tab sits in its loading state forever.
    set((state) => ({
      demoMode: true,
      syncStatus: { ...state.syncStatus, handshakeDone: true },
    }));
  },

  exitDemo: async () => {
    await wipeSeeded();
    set({ demoMode: false });
  },
});
```
